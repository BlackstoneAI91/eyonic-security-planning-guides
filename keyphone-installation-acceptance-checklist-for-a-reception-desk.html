Keyphone Installation Acceptance Checklist for a Reception Desk

Published by Eyonic CCTV.

A practical acceptance checklist for premises managers in Sarawak signing off a keyphone installation at a reception desk, covering handset, headset, speed dials, call handling and handover records.

Why the reception desk deserves its own acceptance test

A keyphone installation is usually accepted at the cabinet or the main console, where the technician can demonstrate lines, extensions and voicemail in a few minutes. The reception desk is a different environment. It is the point where calls, walk-in visitors and staff requests all arrive at once, and it is often staffed by the person with the least time to troubleshoot. If the handset is uncomfortable, the headset is missing, or the speed dials point to the wrong numbers, the problem surfaces on a busy morning rather than during the handover walkthrough.

This checklist is written for premises managers planning ordinary security and communications projects in Sarawak who need to sign off a reception position without becoming a telephony specialist. It treats acceptance as a set of observable tests rather than a judgement about brands. Each item should be demonstrated by the installer and recorded by the manager, with a name against each line. Where a test cannot be completed on the day, record it as open rather than passing it by default.

The checklist sits alongside the other handover documents in a security project. A reception desk often also hosts door-release buttons, a visitor log and a queue ticket dispenser, so the keyphone acceptance should be run in the same session as the access control and queue system checks rather than weeks later.

Before the visit: confirm the desk layout and requirements

Acceptance is easier when the requirements were written down first. Before the installer arrives, confirm how many extensions the reception position needs, which calls must ring at reception, which calls should go straight to a department, and whether the receptionist uses a headset for most of the day. A short written brief, even a single page, gives the acceptance test something to measure against.

Check the physical position too. The handset cable length, the headset socket, the power point and the network or line connection all need to reach the desk without stretching across a walkway. If the desk is being moved or rebuilt, agree the final position before the cabling is fixed. Record who approved the layout, because a later request to shift the phone is a change, not a defect.

Handset and headset checks

Start with the parts the receptionist touches every day. Lift the handset and confirm the dial tone is clear, then make a call to a mobile phone and to an internal extension. Ask the person on the other end whether the voice is clear at normal speaking volume, and repeat the call on the headset if one is supplied. A headset that works but sits uncomfortably will be taken off within a week, so test the fit with the actual receptionist present, not a stand-in.

Check the headset socket or connection type against what was ordered. Confirm the cable is long enough for the way the receptionist actually sits, and that the headset can be muted and unmuted without hunting for the control. Test the handset and headset together: some positions allow either but not both, and the receptionist needs to know which applies.

Record the model of handset and headset supplied, and whether a spare is held on site. This is a documentation point, not a claim about durability. If the headset is a personal item rather than part of the installation, note that clearly so a later replacement is not treated as a warranty matter.

Speed dials, call routing and the numbers that matter

Speed dials are where acceptance most often slips. The installer programs them, the receptionist glances at the list, and a wrong digit is discovered when someone needs the number urgently. Test each speed dial by pressing it and confirming who answers, not by reading the label. Include the numbers the desk actually uses: the site manager, the security desk, the maintenance contact, the neighbouring unit or landlord, and any emergency contact the premises has agreed to display.

Confirm the routing rules in plain language. Which calls ring at reception, which ring a group, and what happens after a set number of rings. Ask the installer to demonstrate a call that arrives while the receptionist is already on another call, because that is the moment the desk is most likely to lose a caller. If voicemail is part of the package, record the greeting, confirm who can retrieve messages, and test retrieval from the reception handset.

Keep a printed speed dial list at the desk and a copy in the handover folder. When a number changes, the list and the programmed button should be updated together. This is a simple governance habit, and it prevents the situation where the label says one thing and the button does another.

Door release, access control and the reception position

Many reception desks also control a door. If the keyphone has a door-release button or is linked to an access control system, test it with the door in view. Confirm which button releases which door, how long the release lasts, and what happens if the button is pressed while the door is already open. Ask the installer to show the release working from the handset and, if a separate access control reader is fitted, confirm the two do not conflict.

Eyonic's published review of smart lock door access notes that smart locks work best when door condition, user roles and backup method are reviewed before installation, and that for business use the choice between a standalone smart lock and an access-control panel is usually checked first. The same discipline applies at reception: decide whether the desk releases the door, whether staff carry cards, and what happens during a power interruption, then test that decision rather than assuming it.

Record who holds door-release authority and how it is removed when a receptionist leaves. A release button is an access permission, and it should appear in the same register as cards and codes.

The acceptance worksheet

Use the table below as a working sheet. The pass column is a record of what was demonstrated, not a score. Any item marked open needs an owner and a date.

Item 1: handset dial tone and call quality, tested to a mobile and an internal extension. Item 2: headset fit, mute control and cable length, tested by the receptionist. Item 3: each speed dial pressed and the answering party confirmed. Item 4: call routing demonstrated, including a call arriving during an active call. Item 5: voicemail greeting and retrieval tested. Item 6: door release tested with the door in view, and the release duration recorded. Item 7: access control or card reader checked for conflict with the release. Item 8: printed speed dial list and handover folder in place. Item 9: named owner for each open item.

As an author heuristic rather than a researched standard, allow roughly one to two hours for a single reception position with a headset and a door release, and longer if call routing is complex or several extensions are involved. The time is a planning aid, not a quotation.

Handover records and what to keep

Acceptance ends with a folder, not a handshake. Keep the programmed speed dial list, the extension list, the voicemail retrieval steps, the door-release authority register and the name of the person who demonstrated each item. Photograph the desk position and the cabinet, and note the model numbers of the handset and headset. If the site also runs CCTV, alarm or gate systems, keep the keyphone records in the same project folder so a future manager can see the whole installation in one place.
