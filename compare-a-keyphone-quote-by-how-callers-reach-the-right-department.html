Compare a Keyphone Quote by How Callers Reach the Right Department

Published by Eyonic CCTV.

A practical guide for Sarawak premises managers on comparing keyphone quotes by mapping caller journeys to written department routing expectations, with a sign-off owner for each decision.

Start With Caller Journeys, Not Equipment Lists

Most keyphone quotes arrive as a list of hardware and a line about programming. That format makes it hard to compare two suppliers, because the part that matters to your callers is buried. Before you read a single quote, write down the journeys your callers actually take. A fictional example: a customer calls the main line, hears a greeting, and needs the service counter. A supplier calls and needs the purchasing desk. An after-hours caller needs a recorded message and a callback promise. Write each journey as one sentence with a start point, a destination department, and what happens if nobody answers. Keep the list to the journeys that occur in an ordinary week, and mark any journey that only happens occasionally. This list becomes the fixed requirement you compare quotes against. It also stops a supplier from quoting a general capability while leaving your specific journey unresolved. The goal is not to design the system yourself; it is to describe the outcome you expect and let each supplier state how their proposal meets it.

Turn Each Journey Into a Written Routing Expectation

A routing expectation is a plain statement of what should happen, written so a supplier can agree or disagree with it. Use a table with five columns: caller type, entry point, department reached, fallback if unanswered, and who confirms it works. For example: "Delivery driver calls the main line, should reach the store receiving desk, fallback is a recorded message asking them to call back during receiving hours, confirmed by the store supervisor." Avoid naming specific features or settings, because that invites a debate about terminology rather than outcomes. Instead, describe the behaviour in ordinary language. If a supplier says a journey cannot be met as written, ask them to propose an alternative in the same five-column format so the difference is visible. This is also where a keyphone system earns its place in the comparison: the question is whether the quoted arrangement lets a caller reach the right department without a staff member acting as a manual switchboard. Keep the table short enough that a busy manager can read it in one sitting.

Give Every Routing Decision a Named Sign-Off Owner

Quotes are easier to compare when each routing expectation has one person who confirms it. Without an owner, a supplier may ask three staff members and receive three answers. Assign owners by role rather than by name where possible, then record the actual person in a separate column that you can update. A fictional example: the service counter journey is owned by the counter supervisor, the purchasing journey by the admin lead, and the after-hours message by the premises manager. Each owner reads the five-column row that applies to them and signs it off in writing before the quote is finalised. This matters because department routing often crosses teams, and a supplier cannot resolve an internal disagreement about who should receive which call. The sign-off owner also becomes the person who tests the journey at handover, which keeps responsibility continuous from quote to acceptance. Record the sign-off date next to each row so you can see which expectations were agreed early and which were added late.

Read the Quote Against Your Table, Line by Line

Once quotes arrive, compare them against your routing table rather than against each other's wording. For each row, note whether the quote states the outcome clearly, states it vaguely, or is silent. A vague statement such as "department routing included" tells you little; a clear statement names the caller type and the department reached. Silent rows are the most important, because they usually become a dispute after installation. Ask each supplier to return your table with a short comment in every row, even if the comment is "not applicable to this proposal". This keeps the comparison on the same footing. Where a supplier proposes an alternative, record it in the same row so you can weigh it against the original expectation. Do not let a supplier replace your table with their own scope document; use their document as supporting detail and keep your table as the master comparison. The result is a short list of genuine differences rather than a long list of similar-sounding promises.

Check the Wider Security Context Before You Commit

A keyphone decision rarely stands alone in a premises project. If the same supplier is also handling other systems, ask how the routing expectations fit with the rest of the site. If your project also covers a burglar alarm system, access control system or smart lock door access, note in your table which supplier owns each handover point, so a caller-routing decision is not left waiting on another trade. Treat those as supplier notes to discuss, not as decisions you can make from a quote alone. Keep the routing table separate from the wider project list, then cross-reference the two.

A Short Comparison Worksheet You Can Reuse

Use one worksheet per supplier, with the same rows in the same order. Suggested columns, offered as an author heuristic rather than a standard: row number, caller type, entry point, department reached, fallback, supplier comment, difference from your expectation, and sign-off owner. Add a final column for the date the owner confirmed the row. Score each row simply as clear, vague, or silent, and count the silent rows first; a quote with fewer silent rows is usually easier to take forward, though price and support still matter. Keep the worksheet to one page so it can be read in a meeting. When you have two completed worksheets, the differences between them become the agenda for your next conversation with each supplier. This is also the point to confirm who will test each journey after installation, and to agree that the test uses the same rows. If your project also includes a queue management system, note separately which supplier owns the counter layout, so the two projects do not compete for the same staff time.

Close the Comparison With a Written Handover Expectation

The last step is to state, before you choose, what a successful handover will look like. Write one line per routing row describing how the owner will confirm it works, using ordinary language rather than technical steps. A fictional example: "Counter supervisor places a test call from an outside line, confirms the service counter is reached, and records the time and outcome." Agree who runs each test and where the results are kept. This turns your comparison into an acceptance record rather than a memory of a conversation. If the supplier's proposal changes after the quote, ask for the affected rows to be re-confirmed by their owners, so the table stays current. Keep the signed table with the rest of the project file, alongside any drawings and manuals the supplier provides.
