Alarm System User Code Management Plan for a Shop

Published by Eyonic CCTV.

A practical plan for Sarawak shop managers to assign, change and revoke burglar alarm user codes among staff, with a register template, rotation schedule and handover steps.

Why a Shop Needs a Written Code Plan, Not Just a Code

An alarm code is easy to set and easy to forget who holds it. In a shop, the people who open and close change over time: a supervisor resigns, a part-timer covers weekends, a landlord's cleaner needs occasional access, and a new manager inherits a panel nobody has documented. If the only record of who knows the code is memory, the shop cannot answer a simple question when something goes wrong: who could have disarmed the system on that date?

A written plan fixes that. It is not a technical document. It is a short register plus a set of rules that say who gets a code, what level of authority it carries, when it changes, and how it is removed. The plan sits alongside your other premises paperwork and is reviewed whenever staffing changes.

This guide is written for premises managers in Sarawak planning an ordinary shop security project. It covers assignment, rotation and revocation of user codes, and it treats the burglar alarm system as one part of a wider premises setup that may also include cameras and door access. Where a brand-specific point appears, it is drawn from Eyonic Security Systems' published material and cited; everything else is general planning advice you should adapt to your own shop and to the instructions supplied with your panel.

Start With Roles, Not Names

The most common mistake in code planning is to start with a staff list and hand out codes person by person. That produces a register that goes stale the moment someone leaves. Start instead with roles, then attach people to roles.

A workable set of roles for a small shop might be:

Owner or director: full authority, including adding and removing other users. Shop manager: daily arm and disarm, plus the ability to add a temporary user if the plan allows it. Supervisor or shift lead: arm and disarm during their shift only. Opening and closing staff: arm and disarm at defined times. Cleaner or contractor: time-limited access, ideally a separate code that is removed after the job.

Each role should carry a written description of what the holder may do: arm, disarm, change their own code, add users, view event logs, or nothing beyond arm and disarm. Keep the descriptions short enough that a new manager can read them in a minute.

Decide early whether any role gets a unique code or whether some roles share one. Shared codes are simpler to administer but destroy accountability, because the event log can no longer tell you which person disarmed the system. As a rule of thumb, give a unique code to anyone who disarms the shop unsupervised, and reserve shared or temporary codes for short, supervised situations.

Build a Code Register You Can Actually Maintain

The register is the heart of the plan. A spreadsheet or a printed sheet in the manager's file is enough, provided it is kept current. Suggested columns, as an example format rather than a standard:

User number or slot on the panel Name of holder Role Code issued date Code changed date Authority level Backup contact Date removed and by whom

Two practical notes. First, record the slot number, not the code itself. Never write the actual code in the register; the register tells you who holds which slot, and the code lives only with the holder and in a sealed record held by the owner. Second, keep a change log at the bottom of the sheet so that a new manager can see the history of additions and removals without hunting through old emails.

Review the register on a fixed cycle. A monthly check that every listed person still works at the shop, and that every person who has left is removed, catches most problems before they matter. Pair this with your alarm handover process when management changes, so the incoming manager signs for the register and the current code list.

Rotation: When to Change Codes and How to Do It Without Chaos

Code rotation is where plans usually fail, because changing a code disrupts the people who open the shop. Treat rotation as a scheduled task with a named owner, not an emergency response.

Triggers worth writing into the plan:

A holder leaves the business, whatever the reason. A holder's role changes so that their authority should change. A code is suspected of being shared or observed. A fixed interval set by the owner, for example every six months, as an author heuristic rather than a rule from any standard. A change of alarm servicing provider or panel.

When you rotate, do it in a defined order. Change the code at the panel first, confirm the new code arms and disarms correctly, then issue it to the holder in person or through a channel you trust, then update the register with the date. If several people share a role, change them together in one session so the shop is not left with a mix of old and new codes.

Keep a small buffer. If the shop opens at a set time, rotate after closing or on a quiet morning, and have the manager on site to test. A rotation that leaves the shop unable to arm overnight is worse than a code that is a month overdue.

Revocation: The Step Shops Skip

Removing a code is the step most often forgotten, because it happens when someone is leaving and attention is elsewhere. Make revocation a checklist item in your staff exit process, with the same weight as returning a uniform or a key.

The revocation steps, in order:

Identify every slot the leaver held, including any temporary code issued for a specific job. Delete or disable those slots at the panel. Test that the old code no longer arms or disarms. Update the register with the removal date and the name of the person who removed it. If the leaver was a keyholder, update the keyholder and response contact list at the same time.

If the panel supports it, review the event log for the period around the departure to confirm nothing unusual happened. This is also a good moment to check that no other slot has been quietly shared.

For shops that also use door access or a smart lock door access setup, run the two revocations together. Eyonic's published review notes that smart locks work best when door condition, user roles and backup method are reviewed before installation, and that for business use the choice between a standalone smart lock and an access-control panel is worth checking. The same logic applies to alarm codes: the role and the backup matter more than the device.

Backup Access and the Single-Person Risk

A shop with one person holding the only working code has a single point of failure. If that person is unreachable, the shop may not be able to arm or disarm when it needs to.

The plan should name at least one backup holder per role, and the backup should be someone who is normally on site, not a distant relative. Record the backup in the register. Test the backup code at a quiet time so that nobody discovers it does not work during a real event.

Separately, keep the owner's sealed record of current codes in a secure place, and decide in advance who may open it and under what circumstances. This is a governance decision, not a technical one, and it should be written down rather than assumed.

If your shop combines an alarm with cameras, note that camera placement and recording are planned separately from alarm codes. Keep the alarm code register and the camera user list as two separate documents, each with its own owner.

A One-Page Plan Template for Your Shop

Use this as a starting structure and adapt it to your premises. It is an author's suggested format, not a standard.

Section 1: Scope. Which panel, which doors and zones, and who owns the plan. Section 2: Roles and authority. The role list with a one-line description of what each may do. Section 3: Register. The table described above, with slot numbers only. Section 4: Rotation rules. The triggers and the fixed interval, with a named owner. Section 5: Revocation checklist. The five steps, plus the keyholder list update. Section 6: Backup access. Named backups and the sealed-record rule. Section 7: Review log. Dates of reviews and who signed.

Run a short test of the plan before you rely on it. Pick a quiet morning, have the manager add a temporary user, arm and disarm with it, then remove it and confirm the old code fails. Record the result in the review log. That single rehearsal catches most of the gaps a written plan can hide.

When you are planning the alarm work itself, keep the code plan separate from the installation scope, and hand both to whoever takes over the shop. For the installation side, the burglar alarm system page is the natural place to start, and it pairs well with a zone map and a handover checklist so that the register, the zones and the keyholder list all describe the same shop.
